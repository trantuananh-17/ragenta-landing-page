# Internationalization

Locales are `en` and `vi`, default `en` (`src/i18n/config.ts`). The
implementation is custom, not next-intl.

## The rule

**No user-facing string in JSX.** Every one comes from the dictionaries, and a
new key is added to **both** `en.json` and `vi.json` in the same change.

`en.json` defines the `Dictionary` type (`typeof en`). `vi.json` mirrors its
shape and is cast. A key present in one and missing from the other renders the
key path on screen — visible by design, but not shippable.

## Reading a translation

- **Server components**: `const dict = await getDictionary(lang)`, then
  `dict.pricing.faq.items`. `src/i18n/dictionaries.ts` is server-only.
- **Client components**: `const { t, raw, locale } = useTranslations("namespace")`.
  `t("key")` for a string, `t("key", { count })` to interpolate, and
  `raw<T>("key")` for an array or object you will map over.
- Pass a dictionary slice as a prop when a server component renders a child that
  should not reach for the context itself — `PostList` takes
  `t: Dictionary["blogIndex"]`.

## Linking

**Always `LocaleLink` from `@/i18n/LocaleLink`, never `next/link`**, for
internal navigation — it prepends the active locale. For a non-link href, or
inside a server component that already knows the locale, use
`localizedHref(locale, path)`.

Both are idempotent: they strip an existing locale prefix before adding one, so
passing `/en/blog` while in `vi` gives `/vi/blog`.

## Structure versus text

Non-textual data that pairs with a translated list stays in code and is merged
by index, with a comment saying so:

    const STEP_DONE = [true, true, false];         // in the component
    const steps = raw<AgentStep[]>("agentSteps");  // from the dictionary

Status flags, coordinates, chart values, model names, slash-command names and
version numbers are code. Everything a reader reads is dictionary.

## Routing

`src/proxy.ts` is Next 16 middleware. The handler **must** be a named
`export function proxy` — Next silently ignores a default export, which would
disable locale detection entirely and stays invisible until someone visits an
un-prefixed URL.

Detection order: the `NEXT_LOCALE` cookie, then `Accept-Language`, then the
default. The same middleware captures UTM and click-id parameters into first-
and last-touch cookies, because browsers strip them from the URL before any
client JS runs.

## Fonts

Inter carries the `vietnamese` subset and is the body stack. Space Grotesk does
not, so `globals.css` routes `--font-heading` back to Inter under
`html[lang="vi"]`. Satori (OG images) ships no Vietnamese glyphs either, so
`og-image.tsx` fetches the exact subset each title needs. Do not remove either.

## Adding a locale

1. `src/i18n/config.ts`: add it to `locales` and `localeLabels`.
2. `src/i18n/dictionaries.ts`: add the loader.
3. `src/i18n/dictionaries/<locale>.json`: mirror `en.json`.
4. `next.config.ts`: extend `LOCALE_PATTERN`. It feeds the cache-header
   matchers, which cannot read the TypeScript constant.
5. Check the font subsets in `src/app/[lang]/layout.tsx`.
